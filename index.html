Jev 導入マニュアル
Claude Code・Codex 両対応

しゃべらないAIを、
自分の道具に入れる。

Jev（ジェブ）は、文章を書かずに「どれか選ぶ・点数・はい／いいえ」だけを返すAIです。
キーの発行から、最初の1件を通すところまで。上から順にやれば終わります。

2026-09-28 更新：公式のキーでも使えるようにしました（Vercel のキーもそのまま使えます）

始める前に

必要なものは2つです。Claude Code か Codex のどちらかがすでに入っていること。それと Jev のキー。公式か Vercel、どちらか1つで大丈夫です（STEP 01）。

向いている仕事

問い合わせの仕分け、クレームの検知、レビューの緊急度づけ。人が毎回、目で見て決めていた判断です。

向いていない仕事

文章を書くこと、理由を説明すること。Jev は一文字も書けません。考える仕事は今までのAIに任せます。

使い分け

考えるのは Claude や ChatGPT、さばくのは Jev。全部を賢いAIにやらせると、遅くて高くつきます。

STEP 01

キーを発行する（公式か Vercel）

Jev は公式サイトから直接使えるようになりました。ただし公式の新規登録は 2026-09-22 から一時停止中です（公式発表）。すでに公式に登録している人は A、まだの人は B で進めてください。

A. 公式のキー

console.typesafe.ai で作る

console.typesafe.ai にサインインして、API Keys の画面でキーを作ります。登録が再開していれば、ここから新しく登録できます。

公式コンソールを開く

B. Vercel のキー

AI Gateway で作る

公式に登録できないときはこちら。Vercel の AI Gateway 経由なら、待たずに使えます（Vercel のアカウントは無料で作れます）。手順は下の 1-1〜1-3 です。

Vercel の Jev のページ

B（Vercel）の手順

1-1

API Keys を開く

Vercel のダッシュボードで AI Gateway → API Keys を開きます。

1-2

Create key を押す

名前は何でも大丈夫です。あとで見分けがつくように jev-test などにしておきます。

1-3

キーをコピーする

この画面を閉じると二度と見られません。STEP 03 でキーを貼り終わるまで、閉じないでください（公式のキーも同じです）。

STEP 02

公式スキルを入れる

使っているほうだけで大丈夫です。入るのは、Jev の使い方を書いた公式の説明書が1本。AIがそれを読んで、判定の部分のコードを書けるようになります。

A. Claude Code の人

claude plugin marketplace add typesafe-ai/skills
claude plugin install typesafe@typesafe-ai

どのフォルダの Claude Code からも使えるようになります

B. Codex の人

npx skills add typesafe-ai/skills --skill typesafe-ai -a codex -y

使いたいフォルダで実行します。全部のフォルダで使うなら -g を足します

入れたあとは、Claude Code / Codex を新しく開き直してください。開いたままだとスキルが見えません。

STEP 03

頼み文を送って、キーを貼る

ターミナルにキーを打ち込む必要はありません。下の頼み文を送ると、AIがキーを入れるファイルを作って開き、そこで待ってくれます。

キーの値をAIが読まない・表示しない書き方になっています

送る前に、2行目の【公式】を、Vercel のキーなら【Vercel】に書き換えてください。

Jev（TypeSafe AI の判定モデル）を試したいです。
私のキーは【公式】のキーです。

キーの種類ごとの使い方
- 公式（console.typesafe.ai で作ったキー）: 変数名は TYPESAFE_API_KEY。呼び出しは公式 SDK（@typesafe-ai/sdk）
- Vercel（AI Gateway で作ったキー）: 変数名は AI_GATEWAY_API_KEY。呼び出しは AI SDK（ai パッケージ 7.0.105 以降）の experimental_evaluate、モデルは typesafe-ai/jev

私はターミナルの操作に慣れていないので、APIキーは .env.local に貼るやり方で進めてください。

進め方
1. このフォルダに jev-test という作業フォルダを作る
2. その中に .env.local を作り、中身は上の変数名で「変数名=」の1行だけにする（値は空）
3. .env.local が git の対象外になっているか確認し、なっていなければ .gitignore に足す
4. .env.local をエディタで開いて、ここで止まる。私に「= の後ろにキーを貼って保存したら『貼った』と送ってください」と伝える
5. 私が「貼った」と送ったら、続きを進める

守ってほしいこと
- キーの値を読まない、表示しない、ほかのファイルに書かない。実行は node --env-file=.env.local のように、ファイルから読み込ませる形にする
- 呼び出し方は、上の「キーの種類ごとの使い方」に合わせる
- 先に typesafe-ai スキルと公式ドキュメント（docs.typesafe.ai）を読んでから書く

やってほしいこと
- 下の問い合わせ3件それぞれについて、次の3つを判定するスクリプトを書いて実行する
  - 担当（注文・配送／返品・返金／その他）
  - 緊急度（低・中・高）
  - クレームかどうか（はい／いいえ）
- 結果を表で見せる。自信の数字（confidence）が低いものには「人が確認」と付ける
- 1件あたりにかかった時間も出す

問い合わせ
- 「昨日届くはずの荷物がまだ来ません。明日の朝に使うので今日中に連絡ください」
- 「領収書の宛名を変えてもらうことはできますか？」
- 「3回問い合わせたのに返事がない。もう返金してほしい」

3-1

ファイルが開く

AIが .env.local を作って開き、「キーを貼ってください」と言って止まります。

3-2

= の後ろに貼って保存

公式なら TYPESAFE_API_KEY=、Vercel なら AI_GATEWAY_API_KEY= のすぐ後ろにキーを貼って保存します。引用符もスペースも要りません。

3-3

「貼った」と送る

問い合わせ3件の「担当・緊急度・クレームかどうか」が表で返ってきたら成功です。

キーをAIのチャットに貼らないでください。貼るのは .env.local の中だけです。問い合わせの文は、自分の仕事のものに差し替えて大丈夫です（個人情報は入れないでください）。うまくいったら、次はこう頼めます。「この判定、Jev でやって」。

つまずいたとき

症状原因対処
認証エラー（401）キーが読めていない.env.local の = の後ろにキーが入っているか、保存したかを確かめる。スペースや引用符を入れない
思ったより遅い通信の時間日本からだと1件0.4秒ほどかかります。公式デモの0.1秒は開発元の条件での数字です
429 が返る無料枠の回数制限少し待ってやり直す。続くなら、公式はコンソール、Vercel は AI Gateway でクレジットを足す
公式に登録できない新規登録が一時停止中（2026-09-22〜）B の Vercel のキーで進める。再開は公式の発表を確認する
モデルが見つからないAI SDK が古い（Vercel のキーの場合）ai パッケージを 7.0.105 以降に上げる
スキルが出てこない入れる前から開いていたClaude Code / Codex を新しく開き直す

知っておいてほしいこと

料金は使った分だけ

公式のキーなら TypeSafe に、Vercel のキーなら Vercel にかかります。Vercel は AI Gateway の Budgets で上限を決めておけます。

人に回すのは、自分で組む

答えと一緒に自信の数字が返ってきます。低いものだけ人が見る、と決めて組みます。自動では起きません。

数字の出どころ

「8秒が0.1秒」「最大400分の1」は開発元の数字です。速度のデモは開発元に有利な条件だと、公式自身が書いています。

Jev はオープンソースではなく、API でだけ使えます。
